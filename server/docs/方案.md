**后端方案书**


1. 目标检测服务负责“找出每个榴莲 + 编号”
2. 多模态/大语言模型负责“基于已编号图片 + 每个目标裁剪图做评分和解释”


---

**一、项目目标**

输入一张榴莲货架图片，后端完成：

1. 识别画面中的所有榴莲
2. 给每个榴莲生成稳定编号（A、B、C...）
3. 生成带编号的标注图
4. 调用大模型逐个评分并给出解释
5. 返回推荐结果、排序结果、可分享图片及结构化数据

输出效果对应你给的三张图：
- 图一 -> 原始上传图
- 图二 -> 后端检测并编号后的图
- 图三 -> 后端汇总大模型评分、推荐最佳榴莲与说明

---

**二、后端总体架构**

建议拆成 5 个模块：


推荐采用：
- `Node.js + NestJS` 做主后端
- `Python` 做视觉识别微服务
- `PostgreSQL` 存任务和结果
- `Redis` 做队列与缓存

---

**三、核心处理流程**

**1. 用户上传图片**
- 小程序上传原图到对象存储
- 后端创建 `analysis_task`

**2. 榴莲检测与编号**
- 检测服务识别图中所有榴莲边界框
- 按“从左到右、从上到下”排序
- 依次编号 A、B、C...
- 生成标注图

**3. 构造 AI 分析输入**
- 输入给大模型两类材料：
  - 带编号的整图
  - 每个榴莲的局部裁剪图
- 同时附上规则化提示词：
  - 成熟度
  - 果形饱满度
  - 刺的密度与粗细
  - 果柄与表皮状态
  - 裂口/黑斑/损伤风险
  - 推荐购买优先级

**4. 大模型输出结构化结果**
要求模型返回 JSON：
- `label`
- `score`
- `summary`
- `reasons`
- `risks`
- `buy_priority`

**5. 结果后处理**
- 校验 JSON
- 分数归一化
- 选出 Top1 / Top3
- 生成最终展示结果与分享图

---

**四、关键技术方案**

**1. 榴莲识别方案**

建议优先选传统 CV/检测模型，不要让 LLM 负责检测。

使用cv-service

**2. 大模型评分方案**

建议采用“视觉输入 + 强约束 JSON 输出”。

模型职责：
- 不负责找榴莲
- 只负责看编号图和裁剪图，对已知目标做解释性评分

评分维度建议：
- 外观成熟度：25
- 果形饱满度：20
- 刺形与壳薄肉厚特征：20
- 新鲜度与损伤风险：20
- 综合购买建议：15

总分 100。

输出示例：
```json
{
  "label": "G",
  "score": 88,
  "summary": "成熟度较好，果形饱满，优先推荐",
  "reasons": [
    "颜色黄绿适中",
    "果形圆润饱满",
    "果刺偏钝且间距适中"
  ],
  "risks": [
    "未见明显开裂，建议尽快食用"
  ],
  "buy_priority": 1
}
```

**3. 提示词工程**

提示词必须明确三件事：
1. 只分析已编号榴莲，不新增编号
2. 必须按统一维度打分
3. 必须返回 JSON，不能输出自由文本

同时要加“保守规则”：
- 看不清时降低置信
- 不允许臆测果肉实际口感
- 只能基于图像外观做判断

**五、后端接口设计**


**1. 创建分析任务**
`POST /api/v1/durians/analyze`

请求：
- 图片 URL 

返回：
- `taskId`
- `status`

**2. 查询任务状态**
`GET /api/v1/durians/tasks/{taskId}`

返回：
- `PENDING | DETECTING | SCORING | DONE | FAILED`

**3. 获取分析结果**
`GET /api/v1/durians/tasks/{taskId}/result`

返回：
- 原图 URL
- 标注图 URL
- 推荐榴莲
- 全部评分列表
- 文案说明

**4. 重新分析**
`POST /api/v1/durians/tasks/{taskId}/retry`

**5. 获取分享图**
`GET /api/v1/durians/tasks/{taskId}/share-card`
